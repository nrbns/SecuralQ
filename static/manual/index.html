1. Start

No manual .env editing required. One command creates the venv, copies defaults, and starts the server. Then open http://127.0.0.1:8080.

Windows:  .\scripts\run_proper.ps1
Linux/macOS: bash scripts/run_proper.sh

Already set up once? Use .\scripts\start.ps1 or bash scripts/start.sh.

Optional model keys and integrations: Settings in the UI (not required to load the project).

3. AI Assistant

On Mission Control and module pages, use the bottom-right Assistant button (not a chat bar on every screen).

  • Action chips: Executive Summary, Root Cause, Attack Path, Ticket, Report, Fix, Playbook, Investigation
  • Ask AI on a finding opens the assistant and stays on the page
  • Workspace opens full AI Workspace · Close or Esc dismisses
  • Pick an Agent; models stay under Advanced

4. Golden path

Import scan→ AI triage→ Jira / assign→ Evidence→ Report
  1. Vulnerabilities → Import scan (real scanner JSON/XML)
  2. Select a finding → use the detail panel
  3. Triage or Triage+Jira
  4. Link evidence / remediations
  5. Export from Reports · check Mission Control counters

5. Native agents & SecuraIQ Sentinel

Continuous host monitoring like Wazuh/EDR, built in — no external product needed.

  • Security Operations → Agents → Enroll agent gives you a one-time install command/token
  • Install as a persistent service: systemd (Linux), launchd (macOS), or a startup Scheduled Task (Windows) — starts on boot, restarts on crash
  • Check-ins report real telemetry (hostname, OS, ports, packages) and keep the agent's online/offline status honest
  • Sentinel runs independently every ~10s, fusing signature matching, behavioral heuristics, ransomware indicators, and file-integrity monitoring (persisted baseline, real add/modify/delete diffs)
  • A detection creates a linked finding, opens an incident for critical/high severity, and pushes live to every open browser — no refresh needed

6. Modules

Vulnerabilities

Filters (severity, status, scanner, owner, search) · table with CVSS/SLA/age · right panel for AI, references, triage, delete.

Web URL Scan

A dedicated page for scanning public web apps (headers, TLS, cookies, sensitive paths, CORS) — install-free. It only accepts public targets: loopback/private/link-local/internal-suffix hosts are rejected before scanning, so it can't be pointed at internal infrastructure. Use a network/VAPT scan from New scan for your own internal hosts.

Compliance

KPI strip (implemented / partial / missing / coverage / evidence / maturity) · framework cards · Open controls · Run gap · delete an assessment (cascades to its remediation tasks).

Assets

Class tiles (server → API) plus inventory table, kept current by scans and native-agent check-ins.

Automation

Visual Trigger → … → Close pipeline, jobs, webhook pointers into Integrations.

XDR/EDR, Integrations & Reports

Live/near-real-time feeds from CrowdStrike, Sophos, SentinelOne, and Defender land in the same SOC views. Connect scanners/Jira/Slack paths that open real import or settings. Export executive/technical reports from Reports.

7. Tools & probing

Open Tools in the assistant. Set a lab/owned target and check Auth before probe tools. Built-ins (DNS, ports, HTTP, headers) work without extra installs.

9. Safety

Use only on authorized labs, CTF ranges, PortSwigger-style training, and systems you own or have written permission to test. No malware, credential theft, or C2 workflows.

The Web URL Scan tool refuses internal/private targets by design (see Modules above). AI output can be wrong — verify remediations before production changes. See Legal.
